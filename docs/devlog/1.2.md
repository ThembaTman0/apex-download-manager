# Apex 1.2: what broke, what I learned, what I decided against

*Draft. Rewrite in your own voice before posting.*

1.2 had one theme: back up what Apex claims with something you can check.
"Fast" and "reliable" are easy words. A test that kills the app ten times and
compares hashes is harder to argue with.

## What broke

**A green tick that lied.** In 1.1.1 the winget step "passed". It hadn't: the
step is allowed to fail without failing the release, so the green tick covered
a `CreateRef` error. My fork of winget-pkgs had fallen behind upstream, and the
token couldn't sync it. I only noticed because the winget PR never showed up.
For 1.2 the step got its own job, a clear failure message that says what to do,
and a token with the right scope. This time it really opened a PR.

**A crash gap I found by reading, not by testing.** While writing the
crash-resume test I read the write path again and found that tokio's
`write_all` returns before the operating system has the bytes. Apex counted
them straight away, and that count is what gets saved for resume. Kill Apex in
that window and a resumed download could skip a few kilobytes and still
"finish". The fix is one flush before counting.

Here's the uncomfortable part: the test passed before the fix too. The window
is microseconds wide, and killing a process at random never landed in it. So
the test doesn't prove this fix; reading the code does. What the test does
prove is the bigger promise, that a download killed ten times still ends up
byte-for-byte right, and it will catch the coarser version of this bug if it
ever comes back.

**My first Settings redesign.** I moved Settings into categories and was quite
pleased with it, until I looked at it next to the rest of the app: a second
navigation rail nested inside the first, a card floating in a dark void on wide
screens, a border around every single setting, and a Save button stranded at
the bottom. It took four rounds to land on what shipped: the categories live in
the main sidebar, each page is one panel styled like the Dashboard's, and Save
is a small pill that only appears when you've changed something. The lesson: a
new page can look fine on its own and wrong next to everything else.

## What I learned

- **Check your own work the way a user would.** I tested the redesign in the
  demo build with a fake backend, then ran the real app before pushing. The
  real app showed a small regression the demo couldn't: the Video page re-ran
  a multi-second tool check every time you opened it.
- **Measure from the right box.** The Downloads toolbar decided when to show
  labels from the window width, ignoring that the sidebar takes 220 px of it.
  At exactly the default window size, it overflowed. Container queries fixed
  it, and the same fix made Settings work in narrow windows.
- **Provenance is not code signing.** Every release file now carries a signed
  record that it was built by this repo's workflow from the tagged source, and
  you can check it with one `gh` command. Windows SmartScreen doesn't read it,
  though, so a new release can still show the "unrecognized app" warning.
  Both are true; I wrote both into DESIGN.md.

## What I decided against

- **A bigger write buffer per connection** (proposed in PR #54). It would cut
  system calls, but the progress counter would run ahead of what's on disk,
  which is the same hole as the crash gap above, only wider. Buffering can come
  back if the counter follows the flushed position.
- **Calling the portable zip "leaves no trace".** It keeps your downloads,
  settings and tools beside the exe, but the window position and the WebView2
  cache still live in your Windows profile. So it says "keeps your data beside
  it", which is true.
- **Claiming the crash fix "prevented corruption".** I never saw it happen, so
  the release notes say "in rare cases" and explain what changed.
- **Showing speed per connection** in the new connection view. Apex doesn't
  measure it, so the view shows each connection's range and progress instead
  of numbers I'd have to invent.
- **A light theme and custom accent colours** for this release. Nice to have,
  but they double the testing for every screen.
